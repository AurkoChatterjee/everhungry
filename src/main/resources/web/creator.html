About this project

EverHungry is a multi-vendor food delivery platform. Customers order from independent restaurants, restaurant owners run their own kitchen dashboards, and drivers claim and deliver orders. Every order moves through a fixed set of statuses, and each change reaches the people involved immediately. While a delivery is under way, the customer sees the driver's position on a map.

How it is built

Backend
Java 17 with Maven. The built-in com.sun.net.httpserver serves a JSON API and the static pages, with no framework.
Database
MySQL over plain JDBC. Tables are created and demo data is loaded on first start.
Multi-tenancy
Each restaurant owner can only read and change their own restaurant, menu and orders. Every query is scoped to the signed-in account.
Order status
A small state machine decides which role may move an order from one status to the next. It is covered by JUnit 5 tests.
Real time
Server-sent events push status changes and driver locations to the browser, with a slow poll as a fallback.
Geolocation
Drivers share browser GPS, or use the built-in ride simulator. Customers and owners pin locations on Leaflet maps.
Frontend
Plain HTML, CSS and JavaScript. The glassmorphism look uses translucent panels, backdrop blur and a space-purple palette, set in Lora, Inter and JetBrains Mono.
Security
Passwords are hashed with PBKDF2. Sessions use HttpOnly cookies. Prices are always read from the database, never from the browser.

Languages
